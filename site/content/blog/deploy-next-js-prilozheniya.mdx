Деплой Next.js приложения на собственный сервер может показаться сложной задачей, особенно если вы ранее не сталкивались с управлением Linux-сервером или настройкой веб-сервера. Однако, следуя пошаговым инструкциям, вы сможете развернуть свое приложение, обеспечить его стабильную работу и защитить соединение с помощью HTTPS. В этой статье рассмотрим весь процесс деплоя: от подключения к серверу по SSH до настройки проксирования через Nginx и установки SSL-сертификата от Let’s Encrypt.

Команды рассчитаны на чистый сервер с Ubuntu и домен, DNS-записи которого — и для самого домена, и для www — уже указывают на IP-адрес сервера.

## Подключение к серверу

Подключаемся по SSH от имени пользователя root:

```bash
ssh root@<IP-адрес_или_домен> -p <порт>
```

> Замените &lt;IP-адрес_или_домен&gt; и &lt;порт&gt; на реальные значения. Если используется стандартный порт (22), параметр -p можно опустить.

## Обновление пакетов

```bash
sudo apt update
```

## Создание нового пользователя и настройка SSH-доступа

```bash
adduser <имя_пользователя>
usermod -aG sudo <имя_пользователя>
```

Отключитесь от сервера (exit) и скопируйте ваш SSH-ключ в нового пользователя:

```bash
ssh-copy-id <имя_пользователя>@<IP-адрес_или_домен>
```

Подключаемся под новым пользователем:

```bash
ssh <имя_пользователя>@<IP-адрес_или_домен>
```

## Отключение доступа по SSH для root

Откройте конфигурационный файл SSH:

```bash
sudo nano /etc/ssh/sshd_config
```

Найдите и измените строку:

```bash
PermitRootLogin no
```

Сохраните файл и перезапустите SSH-сервис:

```bash
sudo systemctl restart ssh
```

> Не закрывайте текущую сессию, пока не проверите во втором окне терминала, что входите на сервер под новым пользователем.

## Настройка SSH-ключей для доступа к GitHub

Сгенерируйте пару ключей:

```bash
ssh-keygen -t ed25519
```

Скопируйте публичный ключ:

```bash
cat ~/.ssh/id_ed25519.pub
```

Добавьте его в <b>Deploy Keys</b> на GitHub (в настройках репозитория: <i>Settings → Deploy keys</i>).

## Клонирование репозитория и установка Node.js

```bash
git clone <ссылка_на_репозиторий>
cd <директория_проекта>
```

Установка nvm и Node.js:

```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash
source ~/.bashrc
nvm install --lts
```

## Установка зависимостей и сборка проекта

```bash
npm ci
npm run build
```

## Установка и настройка PM2 для запуска Next.js

Устанавливаем pm2 глобально:

```bash
npm install -g pm2
```

Запускаем приложение как фоновый процесс:

```bash
pm2 start npm --name <название_процесса> -- start
```

Настраиваем автоматический запуск pm2 при перезагрузке сервера:

```bash
pm2 startup
pm2 save
```

## Настройка брандмауэра (UFW)

```bash
sudo apt install ufw
sudo ufw allow ssh
sudo ufw allow http
sudo ufw allow https
sudo ufw enable
sudo ufw status verbose
```

> Если SSH работает на нестандартном порту, перед `ufw enable` разрешите именно его (`sudo ufw allow <порт>/tcp`), иначе потеряете доступ к серверу.

## Установка и настройка Nginx

```bash
sudo apt install nginx
sudo systemctl enable nginx
sudo systemctl is-enabled nginx
```

Создайте конфигурационный файл:

```bash
sudo nano /etc/nginx/sites-available/<ваш_домен>.conf
```

> Замените <b>ваш_домен</b> на фактическое доменное имя вашего сайта (например, moiseevp.ru).

Начните с обычного HTTP-сервера, который проксирует запросы в приложение. HTTPS и редирект на него certbot добавит на следующем шаге:

```bash
server {
    listen 80;
    server_name <ваш_домен> www.<ваш_домен>;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

Активируйте конфигурацию, проверьте её и перезагрузите Nginx:

```bash
sudo ln -s /etc/nginx/sites-available/<ваш_домен>.conf /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
```

## Настройка HTTPS с Let’s Encrypt

```bash
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d <ваш_домен> -d www.<ваш_домен>
```

Certbot получит сертификат для домена с www и без, добавит в конфигурацию блок HTTPS и настроит редирект с HTTP на HTTPS.

Проверка планировщика обновления сертификатов:

```bash
sudo systemctl status certbot.timer
```

Пробный запуск обновления:

```bash
sudo certbot renew --dry-run
```

## Обновление приложения

Чтобы выкатить новую версию, заберите изменения, пересоберите проект и перезапустите процесс:

```bash
git pull
npm ci
npm run build
pm2 restart <название_процесса>
```

> Сборка перезаписывает файлы, с которыми работает запущенное приложение, поэтому несколько секунд сайт может отвечать ошибками. Чтобы обновлять без простоя, собирайте проект в CI или в отдельной папке и переключайтесь на новую версию после сборки.

Теперь ваше Next.js приложение успешно развернуто на сервере, работает в фоновом режиме с помощью PM2, доступно через доменное имя и защищено SSL-сертификатом.
